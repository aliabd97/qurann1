# تدفق ومسار البيانات (Data Flow) - مشروع القرآن الكريم الكافي

يتبع التطبيق بنية معمارية حديثة وموثوقة تتوافق مع نمط **MVVM (Model - View - ViewModel)** مع الاستعانة بمبادئ **Clean Architecture** الموصى بها في تطوير تطبيقات Android الاحترافية. يشرح هذا التقرير تفصيلياً مسار البيانات بدءاً من مخزن البيانات المحلي وحتى وصولها إلى واجهات المستخدم الرسومية.

---

## المخطط الانسيابي لتدفق البيانات (Flow Topology)

```
[قاعدة بيانات SQLite / Assets]
              │
              ▼
    [QuranDatabase (Room)]
              │
              ▼
         [QuranDao]
              │
              ▼
     [QuranRepository]  <─── (seeding / ensureSeeded() / IO Dispatcher)
              │
              ▼
      [QuranViewModel]  <─── (StateFlow / Prefs / Application Context)
              │
              ▼
[واجهات Jetpack Compose (HomeScreen, StudyReader, MushafReader, etc.)]
```

---

## 1. تفصيل الطبقات ومسؤولياتها الهيكلية

### أ. قاعدة البيانات ومصدر المعلومات (`QuranDatabase`)
* **الرمز**: كلاس `QuranDatabase` الممتد من `RoomDatabase`.
* **المسؤولية**: تعريف قاعدة البيانات التأسيسية وإعداد مصفوفة الجداول الكلية الكريمة (السور، الآيات، الكلمات، الإشارات المرجعية، تدوين الملاحظات، الحزم الحرة).
* **آلية التغذية**: يقوم الملف بالتحقق مما إذا كان ملف الأصول الجاهز `quran_study_db.db` متوفراً في مجلد `assets` ليقوم ببناء القاعدة منه مباشرة عبر `createFromAsset` لتوفير تصفح كامل وسريع للقرآن مباشرة عند التأسيس.

### ب. وسيط الاتصال بالقارئ والمستعلم (`QuranDao`)
* **الرمز**: واجهة `QuranDao` المحتوية على محددات الـ SQL.
* **المسؤولية**: توفير الدوال التأسيسية التي يحتاجها التطبيق والتنسيقات الاستعلامية المحددة مثل دمج الحقول، وتصفية الآيات حسب رقم الصفحة أو رقم السورة، وإدخال/حذف العلامات المرجعية والملاحظات التفسيرية لعدم تداخل البيانات.

### ج. مستودع البيانات وحارس التأسيس والتهيئة (`QuranRepository`)
* **الرمز**: كلاس `QuranRepository`.
* **المسؤولية**:
  * فصل منطق جلب البيانات عن الـ ViewModel.
  * إدارة تهيئة وحقن قاعدة البيانات وتأسيسها وتوليد البيانات الأولية الآمنة (الدينية واللغوية النحوية والتفسيرية) من خلال الكلاس `QuranDbSeeder`.
  * حماية التأسيس عبر خوارزمية قفل متعدد الخيوط `Mutex` لضمان عدم حدوث تكرار أو تجميد للتطبيق أثناء التأسيس الأول للفهرس.
  * ضمان تشغيل جميع الاستعلامات الثقيلة في ممرات خلفية آمنة وموفرة للطاقة وتدعى `Dispatchers.IO`.

### د. العقل المدبر والمدير الفعلي للعمليات وحالات التطبيق (`QuranViewModel`)
* **الرمز**: كلاس `QuranViewModel` الممتد من `AndroidViewModel`.
* **المسؤولية**:
  * الحفاظ على حالات الشاشات وتدفقاتها كاملة وضمان عدم ضياعها وتجنب إعادة بنائها العشوائي عند تدوير شاشة الهاتف أو انتقالها.
  * استخدام أدوات التدفق التفاعلي الحديثة `MutableStateFlow` وعرضها لطبقة العرض كـ `StateFlow` للقراءة فقط حمايةً للبيانات من التغيير العشوائي المباشر خارج مسارات البناء.
  * إدارة تشغيل ومعالجة الملفات الصوتية للقرآن الكريم (تلاوة المقرئ بصوت رقيق وعذب) باستخدام كلاس `MediaPlayer` المدمج مع معالجة استثناءات الانقطاع البرمجي وعدم تجميد التطبيق.
  * استرداد وحفظ تفضيلات المستخدم النشطة لآخر موضع تلاوة (رقم السورة النشطة، ورقم الصفحة النشطة) من خلال كبسولة تفضيلات نظام Android الفورية `SharedPreferences`.

### هـ. طبقة الرؤية والعرض التفاعلي (`Compose View screens`)
* **المسؤولية**: مراقبة تدفق الحالات `StateFlow` في الـ ViewModel وتحويلها إلى واجهات تفاعلية مرنة باستدعاءات `collectAsState` للرسم اللحظي عند تغير قيم البيانات المضمنة بطمأنينة وسلاسة.

## 2. جدول الدوال المنهجية التأسيسية في الطبقات وتوقيعاتها البرمجية

يوضح الجدول التالي الدوال المصيرية المعتمدة لضمان تطابق البيانات، مدخلاتها، مخرجاتها، وهدفها التشغيلي للتأكد من المحافظة عليها عند الانتقال لبيئة Flutter:

| اسم الدالة وشفرتها | موقعها البرمجي | مدخلاتها والمقاييس | مخرجاتها البرمجية | الهدف التشغيلي والسياق |
| :--- | :--- | :--- | :--- | :--- |
| `getSurahs()` | `QuranDao` / `Repository` | لا يوجد | `List<SurahEntity>` | جلب القائمة الطولية المرتبة لـ 114 سورة شريفة للفهرس. |
| `getAyahsForSurah(surahId: Int)` | `QuranDao` / `Repository` | `surahId` (رقم السورة) | `List<AyahEntity>` | جلب آيات السورة المحددة كاملة بالترتيب المتصاعد بالقرآن. |
| `getAyahsForPage(pageNumber: Int)` | `QuranDao` / `Repository` | `pageNumber` (رقم الصفحة) | `List<AyahEntity>` | جلب جميع آيات صفحة كاملة لتخديم نمط مصحف التلاوة (1-604). |
| `getWordsForAyah(ayahId: Int)` | `QuranDao` / `Repository` | `ayahId` (رقم معرّف الآية) | `List<WordEntity>` | جلب البنية الصرفية لكلمات الآية مرتبة لعرض المقطع كلمة بكلمة. |
| `getBookmarks()` | `QuranDao` / `Repository` | لا يوجد | `List<BookmarkEntity>` | استرجاع جميع الآيات التي قام المستخدم بوسمها كعلامة مرجعية.|
| `toggleBookmark(ayahId: Int)` | `QuranRepository` | `ayahId` | لا يوجد | فحص المفضّلة: إدراج الآية إن لم تكن موجودة، وحذفها إن وجدت مسبقاً. |
| `getNoteForAyah(ayahId: Int)` | `QuranDao` / `Repository` | `ayahId` | `String?` (نص الملاحظة) | استخراج التدبرات السابقة للآية إن وجدت، وإرسالها مفرغة في حال العدم. |
| `saveNote(ayahId: Int, noteText: String)` | `QuranDao` / `Repository` | `ayahId`, `noteText` | لا يوجد | تخزين ومزامنة المفكرة النحوية والدينية للآية، وتطهير السجل في حالة الإفراغ. |
| `getPackages()` | `QuranDao` / `Repository` | لا يوجد | `List<PackageEntity>` | حصر الحزم المثبتة أو المتاحة للتنصيب في مكتبة التفاسير والأصوات. |
| `setPackageInstalled(packageId: String, isInstalled: Boolean)` | `QuranRepository` | `packageId`, `isInstalled` | لا يوجد | تركيب الحزمة وحقن ملفاتها بقاعدة البيانات ومختلف حقول الواجهة. |
| `selectSurah(surahId: Int)` | `QuranViewModel` | `surahId` | لا يوجد | تفعيل السورة الحالية وتهيئة آياتها وكلماتها وتحديث مفتاح التفضيلات الموضعي. |
| `selectPage(pageNumber: Int)` | `QuranViewModel` | `pageNumber` | لا يوجد | تحريك نظام التلاوة للصفحة المحددة وتحديث حالة السورة تلقائياً تبعاً لأول آية. |
| `playAyah(ayah: AyahEntity)` | `QuranViewModel` | `ayah` (كيان الآية) | لا يوجد | تشغيل صوت تلاوة الآية الحية للشيخ مشاري العفاسي بنمط الكاش الصوتي عبر الإنترنت. |
| `stopPlayback()` | `QuranViewModel` | لا يوجد | لا يوجد | إيقاف البث الصوتي الجاري وتصفية الذاكرة الفائضة لمشغل الـ Android وموارده. |

## 3. آلية تتبع وحفظ تقدم القراءة النشطة (Active Reading Session)

لضمان عودة المستخدم لنفس الموضع الذي تلا منه آخر مرة بضوابط مثالية، يتبع التطبيق التدفق التالي:
1. عند تلاوة القارئ أو تصفحه لصفحة معينة أو سورة معينة في التطبيق، يستدعي كلاس `QuranViewModel` دوال الاختيار المنهجية (`selectSurah` أو `selectPage`).
2. تحفظ القيم كمتغيرات عددية صحيحة حياً بقاعدة بيانات التفضيلات السريعة للنظام عبر السطر البرمجي الموثق:
   * `prefs.edit().putInt("last_surah_id", surahId).apply()`
   * `prefs.edit().putInt("last_page_number", pageNumber).apply()`
3. عند إعادة تشغيل التطبيق مستقبلاً، يبدأ مشيد الكلاس `init` باستدعاء التفضيلات المخزنة كمرجع قياسي للبدء بإنعاش الواجهة وبمستوى تقدم منسق ومنسجم مع آخر تصفح بشكل ذكي للغاية دون تأخير.
4. يضمن هذا النهج السيطرة الكاملة على مسارات التحرك والتقليل الفوري لمعدلات الفقد والضياع.
